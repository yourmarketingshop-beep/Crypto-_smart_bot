# Crypto Smart Bot – إعادة بناء نظيفة (المرحلة 19)

هذه حزمة مصدر قابلة للفحص أُعيد إنشاؤها لأن ملفات المراحل السابقة لم تكن متاحة في مساحة العمل الحالية. لا تدّعي أنها دمج حرفي مع المرحلة 18.

## المكونات
- `backend/`: FastAPI + SQLite مع حساب افتراضي يبدأ بـ 1,000 USDT.
- `flutter_app/`: واجهة Flutter أولية تعرض الحساب والمراكز والتقرير.
- Binance مستخدم لقراءة بيانات السوق العامة فقط عبر `/market/klines/{symbol}`.
- لا توجد مفاتيح تداول خاصة ولا أي واجهة ترسل أوامر حقيقية.

## تشغيل الخادم
```bash
cd backend
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
افتح `http://127.0.0.1:8000/docs` لتجربة الواجهات. بيانات SQLite تحفظ في `backend/bot.db`.

## الاختبارات
```bash
cd backend
PYTHONPATH=. pytest -q
```

## تشغيل Flutter
```bash
cd flutter_app
flutter pub get
flutter run --dart-define=BOT_API_URL=http://10.0.2.2:8000
```
للهاتف الحقيقي، استبدل `10.0.2.2` بعنوان IP المحلي للكمبيوتر الذي يشغل الخادم، مع وجود الهاتف والكمبيوتر على الشبكة نفسها والسماح بالمنفذ 8000 في الجدار الناري.

## بناء APK
يتطلب Flutter وAndroid SDK مثبتين:
```bash
flutter build apk --release --dart-define=BOT_API_URL=http://YOUR_COMPUTER_LAN_IP:8000
```
لا يوجد APK جاهز ضمن هذه الحزمة، ولم يتم اختبارها على هاتف فعلي. عند النشر خارج شبكة المنزل يلزم إعداد HTTPS وخادم مستضاف آمن.

## حدود النسخة
- المراقبة التلقائية المستمرة بعد إعادة تشغيل الخادم ليست مفعلة في هذه النسخة.
- `/paper/monitor/{symbol}?price=...` يقيّم سعراً يرسله المستدعي فقط.
- التقرير يعرض إجمالي الرسوم وحركة الشراء/البيع، ولا يدّعي حساب ربح محقق FIFO.

## المرحلة 20 – تجهيز Android
تمت إضافة سكربتين داخل `flutter_app/tool/`:
- `prepare_android.sh`: ينشئ مجلد Android الأصلي باستخدام Flutter ويضيف إذن الإنترنت.
- `build_apk.sh`: يجهز Android ويُنشئ APK إصدار Release.

على كمبيوتر Linux/macOS بعد تثبيت Flutter وAndroid SDK:
```bash
cd flutter_app
./tool/build_apk.sh http://192.168.1.10:8000
```
استبدل العنوان بعنوان IP المحلي للكمبيوتر الذي يشغّل FastAPI. للمحاكي يمكن استخدام العنوان الافتراضي `http://10.0.2.2:8000`. على هاتف حقيقي يجب أن يكون الهاتف والخادم على الشبكة نفسها، وأن يسمح جدار الحماية بالمنفذ 8000.

أضيف سير عمل GitHub Actions يدوي/عند تعديل ملفات Flutter لبناء APK ورفعه كـ Artifact. هذا إعداد بناء فقط؛ لم يتم تشغيله أو إثبات نجاحه بعد. لا يوجد APK مرفق في هذه المرحلة لأن Flutter وAndroid SDK غير متاحين في بيئة التنفيذ الحالية.

**تنبيه أمني:** `usesCleartextTraffic=true` مخصص لاختبار الشبكة المحلية أثناء التطوير. لا تستخدمه للنشر العام؛ استضف الخادم عبر HTTPS وعطّل HTTP الصريح قبل التوزيع.

## المرحلة 21 – فحص آلي وبناء APK من GitHub
أصبح سير العمل يفحص اختبارات الخادم أولاً، ثم يبني APK فقط إذا نجحت الاختبارات. عند تشغيله يدوياً يمكنك إدخال عنوان الخادم في `bot_api_url`، كما يمكن ضبط متغير مستودع GitHub باسم `BOT_API_URL` لاستخدامه عند تشغيل البناء بسبب تحديثات الملفات.

**خطوات الحصول على APK من GitHub:**
1. أنشئ مستودعاً جديداً في GitHub وارفع إليه ملفات هذا المشروع بعد فك ضغط ZIP.
2. افتح تبويب **Actions** في المستودع.
3. اختر **Crypto Smart Bot checks and Android APK** ثم **Run workflow**.
4. أدخل عنوان الخادم في `bot_api_url` ثم ابدأ التشغيل. العنوان الافتراضي `http://10.0.2.2:8000` مخصص لمحاكي Android ولا يعمل عادةً على الهاتف الحقيقي.
5. انتظر نجاح مهمتي `backend-tests` و`android-apk`، ثم افتح تشغيل workflow الناجح ونزّل الملف من قسم **Artifacts** باسم `crypto-smart-bot-android-apk`.

**عنوان الخادم:** عند استخدام هاتف حقيقي يجب أن يكون `BOT_API_URL` عنواناً يستطيع الهاتف الوصول إليه. عنوان LAN مثل `http://192.168.x.x:8000` يصلح فقط عندما يكون الهاتف والخادم على الشبكة نفسها. للاستخدام عبر الإنترنت استضف FastAPI على HTTPS. لا تضع أسراراً أو مفاتيح خاصة في عنوان الخادم أو في التطبيق.

هذا التعديل يجهّز عملية البناء والفحص فقط؛ لم يتم تشغيل GitHub Actions من هذا المستودع ولم يتم إنتاج APK أو تثبيته على هاتف في هذه البيئة. استمر وضع التشغيل PAPER ONLY ولا توجد أوامر تداول حقيقية.


## المرحلة 22 – المؤشرات الفنية داخل لوحة التحكم

- أضيف المسار `GET /market/indicators/{symbol}` لعمل تحليل من بيانات شموع Binance العامة المكتملة فقط.
- المؤشرات المحسوبة: RSI(14)، EMA(12/26/50)، وMACD مع خط الإشارة وHistogram.
- يحتاج الحساب إلى 35 شمعة مكتملة على الأقل؛ وقد لا تتوفر EMA50 في السلاسل الأقصر.
- أضيفت لوحة اختيار BTCUSDT وETHUSDT وSOLUSDT داخل Flutter وعرض السعر والمؤشرات.
- هذه مؤشرات تحليلية فقط ولا تنفذ صفقات ولا تقدم ضماناً للربح. يبقى النظام PAPER ONLY.

### اختبار المرحلة 22
شغّل `PYTHONPATH=. pytest -q` من مجلد `backend`. تشمل الاختبارات حساب المؤشرات في سوق ثابت، رفض البيانات القصيرة، واختبار المسار باستخدام بيانات شموع اختبارية دون الاعتماد على اتصال خارجي.


## المرحلة 23 – الإشارات والاختبار التاريخي الافتراضي

- أضيف `GET /market/signal/{symbol}` لإصدار BUY أو SELL أو HOLD وفق اجتماع ثلاثة شروط RSI وMACD وEMA12/26.
- درجة التوافق تعرض عدد الشروط المتوافقة فقط، وليست احتمالاً للربح أو دقة تنبؤ.
- أضيف `GET /paper/backtest/{symbol}?limit=500` (الحد الأدنى 38 طلباً لأن آخر شمعة قد تكون مفتوحة) لاختبار تاريخي على شموع Binance العامة المكتملة.
- يمنع الاختبار النظر إلى المستقبل: تُحسب الإشارة من الشموع المغلقة حتى اللحظة، ويكون التنفيذ الافتراضي عند افتتاح الشمعة التالية.
- يفترض الاختبار رصيداً مستقلاً 1000 USDT ورسوم 0.1% لكل عملية شراء أو بيع. لا يشمل الانزلاق السعري أو فروق الأسعار، ولا يغير حساب التداول الافتراضي الجاري.
- أضيفت شاشة تعرض الإشارة ودرجة توافق الشروط وزر تشغيل الاختبار وملخص نتيجته.
- تبقى كل الوظائف تحليلية/تجريبية فقط، ولا توجد أوامر Binance تداول حقيقية.

### اختبار المرحلة 23
شغّل `PYTHONPATH=. pytest -q` من مجلد `backend`. تشمل الاختبارات قواعد الإشارات، توقيت التنفيذ في الشمعة التالية، احتساب الرسوم، وكون الاختبار التاريخي لا يغير رصيد الحساب الافتراضي.

## المرحلة 24 – حاسبة حجم المركز وإدارة المخاطر

- أضيف `POST /paper/risk/size` لحساب كمية مركز شراء افتراضي من النقد المتاح، وسعر الدخول، ووقف الخسارة، ونسبة المخاطرة.
- نسبة المخاطرة محدودة بحد أقصى 2% من النقد المتاح لكل تقدير. يتم أيضاً تقييد الكمية بما يمكن شراؤه نقدياً بعد تقدير رسوم الدخول 0.1%.
- يعرض الرد قيمة المركز، والكمية، ورسوم الدخول المقدرة، والخسارة التقديرية عند وقف الخسارة. الحساب لا ينشئ صفقة ولا يحجز رصيداً ولا يغيّر المراكز.
- أضيفت في Flutter حاسبة لإدخال سعر الدخول ووقف الخسارة ونسبة المخاطرة وعرض الحجم التقديري.
- الحساب يفترض مركز شراء (Long)، ولا يضمن تنفيذ الوقف بالسعر المحدد؛ لا يشمل رسوم الخروج أو الانزلاق السعري أو فجوات الأسعار.

### اختبار المرحلة 24
شغّل `PYTHONPATH=. pytest -q` من مجلد `backend`. تشمل الاختبارات احترام ميزانية المخاطرة، وحد 2%، وتقييد الحجم بالنقد المتاح، وعدم تغيير رصيد المحاكاة أو المراكز عند استخدام الحاسبة.
